# workflow-upgrade

主体是 `AGENTS.md`：它由模板整份生成，项目里的本地改动会在升级时被覆盖。`docs/` 骨架只补齐缺失文件，已有文档一律不动。

## 执行顺序

从本次请求确定目标仓库路径，没给就用当前工作目录。直接调用本技能目录下的 `run.py`，它会定位源码仓库并转调共享脚本：

```bash
# 1. 只读：看版本差和 diff
python <SKILL_DIR>/run.py --root <目标仓库>

# 2. 开发者明确同意后，才写入
python <SKILL_DIR>/run.py --root <目标仓库> --write
```

先取得本 SKILL.md 所在目录的绝对路径再替换 `<SKILL_DIR>`。不要自己拼 `<SKILL_DIR>/../../scripts/upgrade_project.py`：技能目录常以软链或目录联接挂载，相对路径里的 `..` 会在链接处被错误解析。

差异较多时用 `--full-diff` 看全部；只想判断有无漂移（CI、提交前钩子）用 `--check`，有差异时退出码为 1 且不写文件。

## 判断与边界

- **先报告再动手**：把版本从哪个到哪个、实质变更点讲清楚，取得明确同意后才加 `--write`。
- **本地新增内容**：项目 `AGENTS.md` 里有大段自定义条款时不要直接覆盖。先说明这些属于项目特有约定，应迁移到 `docs/` 下对应长期文档，迁移完再升级。
- **版本标记缺失**：按首次接入处理，正常走 diff + 确认流程，写入后会自动带上 `agents-md-template:` 标记。
- 不做备份：`--write` 会整份覆盖 `AGENTS.md`，回滚依赖目标仓库的 Git 历史；写入前先只读跑一次看清 diff，项目里有未提交的本地改动时先由开发者自行提交或另存。仅补齐 docs 骨架时不会改动它。
- 脚本只创建缺失的 `docs/` 骨架，不删除、不改名、不合并已有文档；文件名与骨架不一致时提示开发者自行决定。
- 不修改 `run.py` 与共享脚本；要改行为请改源码仓库里的 `scripts/upgrade_project.py`。

## 完成后

交代两件事：版本从哪个到哪个、`AGENTS.md` 的实质变更点（不再产生备份文件）。
